# Remaking

The tools and approaches available for remaking are listed in `remake-tools.md`; each one's usage, cost, and how to hook the user up has its own doc: `chatcut.md`, `capsule-cinema.md`, `diy.md`.

## Follow these steps

The report's "remake it yourself" section first classifies the video's type (talking-head, tabletop, AI short, beat-synced montage, etc. — 15 categories, inferred from the footage-category mix, live-action format, audio type, and cutting rhythm), then lists steps in the order that type is actually produced. Each step states only numbers actually measured from this video (camera position, lighting, cutting rhythm, subtitle style, audio source, generation units) plus this tool's own files and commands — leave out anything that wasn't measured. Give this section first when the user wants to do it themselves; if the type was misjudged, say so and give the steps in the order for the correct type. Don't add experience-based numbers beyond what was measured.

## Run one command first

`rea-video remake out/ref`: rebuilds still images using their measured motion (code-render shots default to an original-footage placeholder — it's best to hand those to an HTML video framework to redo; add `--code` to auto-run `code-remake` for a quick draft). Shots found in `remake/results.json` (produced by `remake-run`) and `remake/mine.json` (supplied by the user, or manually generated on a website — format `{"results": {"<shot id>": {"video": "/absolute/path"}}}`) are cut in; everything else gets an original-footage placeholder; everything is assembled on the original timeline with subtitles layered back on. `remake/status.md` writes out, shot by shot, how it's currently handled and what's still needed. Each time you get a new shot, add it to `mine.json` and run it again. The sections below cover the details for each shot type.

## Which model to use

- The model, whether to redo the whole thing or just the AI shots, and what to swap — all go into `remake/intent.yaml` (see SKILL.md's "Remaking" section); `rea-video plan out/ref` produces the plan from it. Ask first if the user hasn't said which model.
- The prompt in the report for each unit is a draft. Turn it into the final version per the writing style `rea-video models <id>` prints, and put it into `remake/prompts.json`: how time and shots are split up, how reference material is referred to, how to phrase dialogue and anything you don't want; in first-frame / first-and-last-frame mode, keep only motion and camera movement. `rea-video plan` checks it against that model's format rules.
- How to pick frames, erase text, and set up first/last frames: `rea-video models keyframes`.

## How to remake each shot type

- **AI-type shots** (live-action shots count too when `generate: all`): fit consecutive shots into the same generation call wherever possible. Pick the input method by what the model can take: if it accepts a reference video, erase the subtitles from that stretch of the original and feed it as `@video1` — the model follows its shot composition and pacing; if it can't take a reference video but can take multiple shots and images per call, give one original frame per shot to fix the composition; only fall back to per-shot first/last frames if neither works. Write what needs to be swapped in from the intent's images and descriptions; for anything described in text only, splitting it into more calls means more chances for it to look different each time — so generate in as few calls as possible, write composition into the prompt for any shot that doesn't have an image slot to spare, and only split things more finely once you actually have a reference image for it. This can be run automatically via capsule-cinema (this costs money — use `--dry-run` first and get the user's go-ahead; see `capsule-cinema.md`).
- **Still-image pans, freeze frames**: rebuilt locally using the measured motion parameters.
- **Code render**: redo with an HTML video framework (like HyperFrames, see `hyperframes.md`): follow `video/rhythm.md` for cut points, transitions, and per-shot keyframes, and the report's "code composite" section for layout, color scheme, and elements. `code-remake` only produces a quick draft — dark-background graphics like particles, point clouds, and data visualizations can come close to the original, but illustrated-character motion and deformation-based transitions can't be reproduced this way. Run `rea-video code-remake out/ref` when you need a draft. It writes `out/ref/code/` (`spec.json` with one entry per scene, `render.py` as the renderer, `overlays.ass` for text) from each scene's sample points or matting, measured motion, and background light in the breakdown package's `frames/`, matches amount and brightness to the original scene by scene, renders `code/remake.mp4`, and scores it against the original.
  - Start every further change from this version: first adjust the numbers in `spec.json` (particle count `count`, size `dot`, brightness `gain`, motion `motion`, background glow `glow`); to swap in a new shape, replace `points` with your own point file; only edit `render.py` — or rewrite it as Remotion/Three.js — for an effect the original doesn't have. Rerun the same command after editing; an edited `spec.json` is kept, and only `--reset` rebuilds from scratch. `python code/render.py --frame 12.5` renders just one frame to preview.
  - Follow the `advice` under `lowest_scenes` in the output, fixing the lowest-scoring scene first, checked against `code/compare/compare_worst.jpg`.
  - The report's "code composite" section's per-shot visual description, plus the element screenshots and keyframe strip under `shots/`, fill in what the tool can't measure: how things enter, what a shape means.
- **Dance/action shots** (flagged by `performance.move` during visual review): don't use first/last frames — the report's "motion-driven" section gives a route and prompt: by default, use the original footage directly as the reference video; only switch to a depth map or a white-model rig if the original background is too busy or the new scene is very different; keep direct reference when expression needs to be preserved (depth/white-model loses facial expression). Run `rea-video drive out/ref` first to produce a driving video with subtitles erased and cut at pauses (`drive/README.md` has the details per segment); check `drive/segments.jpg` first to see whether hands/feet got erased by mistake. Once a segment is generated, add it to `drive/results.json`, then run `rea-video drive out/ref --join`, then `rea-video remake`.
- **Real assets**: list them so the user can supply them; once you have them, add them to `remake/mine.json` and run `rea-video remake` again, or cut them into ChatCut matching the original's pacing.
- **Performance and emotion**: the report's "Performance & emotion" section writes out each shot's emotion, expression, action, and tone — the generation-unit prompts already carry the expression and action. When rewriting a prompt, keep the visible expression and action — don't swap them for words like "happy" or "sad," and don't exaggerate the amplitude; for a shot with dialogue, record the toned dubbing first, then have the picture perform to match the audio.
- **Audio**: prepare three tracks separately — TTS (matching each line's tone from the script table), BGM (matching BPM/key/mood), sound effects (matching timestamps).
- **Editing/packaging (subtitles, styled text, stickers)**: doesn't go into generation. The generation model only produces a clean person and scene; the packaging layer is layered on last, following the "editing/packaging layer" timeline — that way text never gets blurred by the model, and changing the copy only means editing the packaging layer.
  - References pulled from the original (reference video, keyframes, first/last frames) are under `remake/refs/`, with subtitles, styled text, and persistent text already erased.
  - When changing the copy, place styled text and stickers on the matching line of the new copy per the report's "anchored to dialogue," rather than reusing the original timestamps; "persistent layers" are overlaid once for their whole span.

See `diy.md` for how to cut the user's own footage, or video manually generated on a website, back into the original timeline; see `capsule-cinema.md` for automatic generation with capsule-cinema.
