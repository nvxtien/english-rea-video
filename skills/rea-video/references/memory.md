# Remembering the user's corrections and preferences

- When the user points out a shot was misjudged ("this is stop motion, not AI," "this part is my own footage"): run
  `rea-video correct out/ref --shots 3,5 --label stop_motion --note "<the user's own words>"` (`--label` is the category the user named — see `taxonomy.md` for names: stop motion is `stop_motion`, a still image + pan is `still_motion`; you can also use `--start/--end` to give a time range, or `--shots all` for the whole video; for a real asset use `--real yes|no`).
  This immediately updates the verdict and report, and is logged to `~/.rea-video/corrections.jsonl`; decomposing the same file again will apply it automatically, and the same type of shot will be flagged during review.
- When the user states a standing preference: for anything that maps to a parameter, use `rea-video prefs engine kling2.1`, `prefs vlm on`, `prefs env_file <path>`, `prefs reviewer <name>`, `prefs capsule_root <capsule-cinema path>`; for anything else, record it with `rea-video prefs --note "keep reports short, focus on the remake plan"` — `rea-video memory` will show it next time, and you should adjust your reply accordingly.
- Only record what the user explicitly says — don't write your own guesses as corrections. A correction doesn't automatically change classification weights; once a few have accumulated, export them as an eval sample with `rea-video memory --export-labels eval/user_labels.yaml`, then evaluate and tune the rules following the dev conventions (repo `docs/dev/evaluation.md`).
