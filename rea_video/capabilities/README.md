# Capability Map

> Models are `rea-video`'s "instruction set." Reverse-engineering a video means mapping every shot to the most controllable set of generative model calls or code renders available under current model capabilities.
> This is that instruction-set manual: structured as data, schema-validated, dated by verification, and time-bounded.

For the human-readable summary table, see [MATRIX.md](MATRIX.md) (auto-generated by script).

## Three-Layer Architecture

```
signals (per-shot features detected during breakdown)
   │  routing.yaml
   ▼
primitives (vendor-agnostic capability primitives)  ◄── primitives.yaml
   │  primitives field in models/*.yaml
   ▼
models (specific models/tools with limits, pricing, licenses, and provenance)
```

- **`primitives.yaml`:** 43 primitives covering analysis, image, video, character driving, 3D, audio, code rendering, and post-processing, plus 16 verification metrics. Routing only references primitives, so rules don't break when swapping vendors.
- **`models/*.yaml`:** One entry per model, organized into category files:
  - `video`: video generation & editing
  - `character`: motion transfer, talking avatars, lip-sync, virtual try-on
  - `image`: image generation & editing
  - `audio`: audio generation & processing
  - `threed`: 3D generation
  - `analysis`: VLMs and deterministic tools used for breakdown
  - `render-post`: code rendering, compositing, upscaling, frame interpolation
- **`prompting.yaml`:** Prompting conventions and keyframe requirements per model, indexed by model ID:
  - Structure, language, length, how to write multi-shot & timing, referencing source assets, dialogue/audio, negative constraints, camera motion, first-frame vs. first/last-frame modes, frame-image requirements, auto-rewrite toggle, and known quirks.
  - `basis` marks primary provenance; `unverified` lists unverified or conflicting claims; `keyframes` at the top covers universal keyframe rules across all models.
  - Inspect via `rea-video models <id>`; whichever model a remake plan targets, its prompting rules are attached.
- **`routing.yaml`:** Contains:
  - Signal definitions
  - Two-level splitting rules (edit shots → generation units → layers)
  - Visual routes `R01–R16`, audio routes `A01–A05`, post-production routes
  - Cost policies, user-confirmation checkpoints, and prompting discipline

## Model Entry Fields

| Field | Description |
|---|---|
| `id` | Globally unique, lowercase kebab-case |
| `status` | `ga` / `preview` / `limited` / `deprecated` / `shutdown`; router skips `shutdown` |
| `access` | `app` / `api` / `api-aggregator` / `open-weights` |
| `primitives` | Supported primitives |
| `limits` | Bounds on duration, resolution, reference count, keyframes, etc.; `exclusive_inputs` lists input groups that cannot be combined in one call (e.g., first/last frames vs. reference images) so the planner picks one mode per generation unit |
| `cost.usd_per_s` | Relative cost used for route ranking and budget estimation |
| `license` | `commercial: true / false / conditional` with notes; `regions_excluded` lists regional restrictions |
| `verified.basis` | Provenance trust order: `probe` (self-tested) > `user` (user-tested) > `vendor` (official) > `third-party` > `knowledge` (training/common knowledge) |
| `confidence` | `high` / `medium` / `low` |
| `probe_scores` | Probe test scores (reserved, auto-populated by probes) |

## Maintenance Workflow

1. **Add or update a model:** Edit the corresponding `models/*.yaml` with source URLs and `verified.date`; for video models, also add prompting rules in `prompting.yaml`.
2. **Validate:** Run `python3 scripts/validate_capabilities.py --matrix`. Checks schema, referential integrity, whether preferred models actually support the primitive, primitive coverage gaps, and stale entries (> 90 days).
3. **User-tested findings** (e.g., *"GPT Image 2.5 renders Chinese text best"*): record under `strengths` with `basis: user`.
4. **Deprecating/shutting down a model:** Set `status: shutdown`, keep the entry, and remove it from routing rules.
5. **Probes (P1):** Small test suites per primitive (`probe` field in `primitives.yaml`) run automatically on new models and write scores back to `probe_scores` for route ranking.

## Known Backlog

- Many entries' release months and detailed specs come from third-party roundups (marked `medium` or `low`) and need verification via probes or official docs.
- Several models are fine-tuned variants of MiniMax H3 (Pika H3 Flex, HeyGen Video 1, Utopai X, P-Video-2-Pro); licensing must be checked alongside H3's terms.
- Models lacking official prompting documentation (omitted from `prompting.yaml` for now): HappyHorse 1.0, SkyReels V4, Grok Imagine Video 1.5 Lite, Utopai X, P-Video-2-Pro, Higgsfield Genjutsu.
- Excluded until official pages exist (rumors only): Veo 3.2 / 4, Gemini Omni Pro, Runway Gen-5, Luma Ray 4, Hunyuan Video 2.0, Midjourney Video V2.
- Not yet cataloged: Jimeng Image, Kolors Image, Jianying / CapCut avatar & export capabilities, and domestic avatar tools such as ChanJing / ShanJian (no model-level release specs found).
